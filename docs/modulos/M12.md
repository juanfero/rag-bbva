## 1. Objetivo
Cumplir el requisito obligatorio R2 del caso: **Dockerfile + docker-compose que levantan todo el sistema con un solo comando** (`docker compose up -d --build`), sin scrapear el sitio en el arranque y con el historial persistente.

## 2. Alcance
- Incluye:
  - snapshot versionado de datos limpios y embeddings;
  - comando `bootstrap` (servicio `init`);
  - Dockerfile multi-stage;
  - compose con `qdrant`, `init`, `api` y `ui` (healthchecks, `depends_on` por condición, volúmenes, puertos configurables);
  - smoke test automatizado;
  - README con Docker como camino principal.
- No incluye:
  - imagen con los modelos dentro (se descargan una vez al volumen);
  - despliegue en la nube;
  - TLS ni autenticación (L-14).

## 3. Diseño
- **Snapshot** (`snapshot/`, 8,5 MB; ADR-019):
  - `documents.jsonl` (597 documentos limpios, 2,45 MB);
  - `embeddings/intfloat--multilingual-e5-small.npz`: la caché podada a los 3546 chunks (3544 vectores distintos: dos chunks comparten texto), 6,35 MB;
  - `MANIFEST.json` con SHA-256.
  - Lo genera `scripts/make_snapshot.py`, que falla si a la caché le falta algún vector.
- **`bootstrap`** (`src/rag_bbva/indexing/bootstrap.py`, comando `rag-bbva bootstrap [--force] [--sin-modelos]`):
  1. copia los documentos y la caché del snapshot solo si faltan (no pisa datos existentes);
  2. cuenta los puntos de la colección (una colección inexistente cuenta como 0; Qdrant caído hace fallar el arranque);
  3. indexa solo si hay 0 puntos o con `--force`;
  4. carga embedder y reranker (descarga los modelos al volumen).
- **Dockerfile** multi-stage:
  - la etapa `build` crea un venv con torch CPU (índice de PyTorch) y el proyecto;
  - la final copia el venv y el snapshot y crea el usuario `app` (uid 1000) dueño de `/app/data` y `/app/models`, para que los volúmenes con nombre hereden los permisos;
  - `HF_HOME=/app/models/.hf`; CMD `serve`.
  - La página Métricas (`ui/pages/`) se declaró como *package data*: sin eso no viajaba en la instalación (verificado dentro de la imagen).
- **`docker-compose.yml`:**
  - servicios `qdrant`, `init` (`bootstrap`, `restart: "no"`), `api` (`serve --host 0.0.0.0`) y `ui` (`ui --host 0.0.0.0 --api-url http://api:8000`);
  - cadena `qdrant` healthy → `init` completado con éxito → `api` healthy → `ui`;
  - el healthcheck de la API acepta un 503 de `/health`, porque sin clave del LLM la UI debe arrancar igual para mostrar ese estado;
  - volúmenes `qdrant_data`, `app_data` (historial, datos, caché) y `model_cache`;
  - `env_file: .env` (la clave entra solo por ahí); `QDRANT_URL=http://qdrant:6333` en `environment`, que tiene prioridad sobre `.env`;
  - puertos `127.0.0.1:${API_PUBLISHED_PORT:-8000}` y `${UI_PUBLISHED_PORT:-8501}`.
- **`scripts/smoke_test.sh`:** espera a la API; exige Qdrant `ok` con puntos y la clave configurada; hace una pregunta (200 y al menos una fuente); revisa el historial (2 mensajes) y la UI (`/_stcore/health`). Gasta 1 llamada al LLM.
- **Configuración nueva:** `SNAPSHOT_DIR`, `API_PUBLISHED_PORT`, `UI_PUBLISHED_PORT`. Dependencia de desarrollo: `pyyaml` (pruebas del compose).

## 4. Decisiones y supuestos
- **ADR-019:** snapshot versionado, `init` idempotente y modelos en volumen (no en la imagen).
- La caché de embeddings va en el snapshot para no re-embeber en CPU: 3546 chunks indexados en ~10 s en vez de ~2,5 min.
- El healthcheck de la API mide que esté **viva**, no que todo esté sano: el estado degradado lo informa `/health` y lo muestra la UI.

## 6. Evidencia manual
Prueba de aceptación en un **clon limpio** de la rama (solo lo versionado: sin `data/` ni `models/`), con el `.env` copiado y puertos `API_PUBLISHED_PORT=8020` y `UI_PUBLISHED_PORT=8521`. En esta máquina el 8010 y el 8501 los ocupaban la API y la UI locales de Juan Felipe; usarlos con solo dos variables también prueba que los puertos son configurables.

### 6.1 Primer intento: imagen construida desde cero
`docker compose up -d --build` terminó con código 0 en **~10 min**. De 14:05 a ~14:10 se construyó la imagen (torch CPU, 196 MB); de 14:10 a 14:14 `init` descargó los modelos; después `api` y `ui` quedaron *healthy*.

## 7. Problemas encontrados y solución
- **La página Métricas no viajaba en la imagen:** `ui/pages/` no es un paquete, así que `pip install .` no la copiaba. Se declaró como *package data* y se verificó dentro de la imagen.
- **Prueba "limpia" que no lo era:** el clon se llamaba igual que el proyecto de desarrollo y Compose reutilizó su volumen de Qdrant. Se repitió con un nombre de proyecto propio (`-p ragbbva-limpio`). En una máquina realmente nueva no pasa, porque no hay volúmenes previos.
- **Puertos ocupados por servicios locales del usuario:** no se tocaron; se usaron 8020 y 8521 por `.env`.
- **El primer intento detuvo el Qdrant de desarrollo** (al bajar el proyecto con el mismo nombre). Se restauró al terminar.
- **Manifiesto:** la primera versión decía "chunks: 3544", que en realidad era la cantidad de vectores distintos. Ahora informa ambas cifras: 3546 chunks y 3544 vectores.
