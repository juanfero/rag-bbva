## 1. Objetivo
Dejar el esqueleto que reutilizan todos los módulos: repositorio, estructura de paquetes,
configuración externalizada, jerarquía de excepciones, logging, CLI y Docker base.
Cubre R1 (Python), R2 (base Docker), R3 (historial de commits), B2 (base de manejo de errores)
y B3 (configuración externalizada).

## 2. Alcance
- Incluye:
  - `git init` en `main`, `.gitignore` (con `.env`) desde el primer commit de código.
  - `pyproject.toml` (setuptools, layout `src/`) con config de `ruff` y `pytest` (marcadores `integration` y `slow`).
  - Estructura de `00_VISION_GENERAL.md §5`: subpaquetes vacíos (solo docstring) en `src/rag_bbva/`, `tests/{unit,integration,fixtures}`, `eval/`.
  - `config.py`, `.env.example`, `exceptions.py`, `logging_conf.py`, `cli.py` (comando `version`).
  - `Dockerfile` base y `docker-compose.yml` mínimo (servicio `api` con comando placeholder).
- No incluye:
  - Lógica de scraping, indexación, LLM, memoria, API o UI (M1 en adelante).
  - Servicios `qdrant`, `init`, `ui` y volúmenes en compose (M12).
  - Dependencias de módulos futuros (ver ADR-007).

## 3. Diseño
- Componentes / archivos creados:
  - `src/rag_bbva/config.py`: `Settings` (pydantic-settings) con las 25 variables de §7 y `get_settings()` con `lru_cache`.
  - `src/rag_bbva/exceptions.py`: `RagBbvaError` (mensaje + `detail` técnico) → `ScrapingError`, `ProcessingError`, `IndexingError`, `RetrievalError`, `LLMError`, `HistoryError`, `ConfigurationError`.
  - `src/rag_bbva/logging_conf.py`: `JsonFormatter` (una línea JSON por evento; los `extra` se emiten como claves) y `configure_logging(level)`.
  - `src/rag_bbva/cli.py`: app Typer (`rag-bbva` / `python -m rag_bbva.cli`); el callback configura el logging.
  - `Dockerfile` (python:3.11-slim, usuario no root uid 1000), `.dockerignore`, `docker-compose.yml`.
- Patrones de diseño aplicados:
  - **Singleton vía caché**: `get_settings()` con `lru_cache(maxsize=1)` evita releer y revalidar la configuración.
- Configuración nueva (`.env`): todas las variables de `00_VISION_GENERAL.md §7`, documentadas en `.env.example`.
  Validaciones: rangos por campo (`gt`/`ge`), enums (`LLM_PROVIDER` ∈ {xai, fake}, `LOG_LEVEL`),
  y reglas cruzadas `CHUNK_OVERLAP < CHUNK_SIZE` y `RERANK_TOP_N <= RETRIEVAL_TOP_K`.

## 4. Decisiones y supuestos
- ADR-006: `XAI_API_KEY` es opcional en `Settings`; su presencia se exige al crear el proveedor xAI (M7).
- ADR-007: las dependencias se agregan al `pyproject.toml` en el módulo que las usa.
- Se agregó `ConfigurationError` (no listada en el plan) para errores de configuración detectados en ejecución, p. ej. falta la clave de xAI.
- Se agregó la validación `RERANK_TOP_N <= RETRIEVAL_TOP_K` (no estaba en el plan): el reranker no puede devolver más candidatos de los recuperados.

## 7. Problemas encontrados y solución
- **Python local 3.11.0rc1:** el `python3` del sistema es 3.10 y `/usr/bin/python3.11` era una versión candidata (3.11.0rc1). **Resuelto tras el cierre:** el `.venv` se recreó con Python **3.11.17** estable instalado con `uv` (0.12.22); la imagen Docker usa `python:3.11-slim`.
- **Bind mount `./data` creado como root:** al levantar el compose, Docker creó `data/` como root y el contenedor (uid 1000) no podría escribir. Como el comando placeholder no usa datos, se quitó el volumen del compose de M0; los volúmenes se definen en M12.
- **Ruff RUF002:** guion largo (–) en un docstring; se reemplazó por texto.
